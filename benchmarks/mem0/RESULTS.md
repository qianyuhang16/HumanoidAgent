### 修改了什么

1. 在 IK 之前建立 VLA 的视觉 anchor，接近后更新当前观察；不再只使用接近后的
   场景作为技能初始记忆。`handoff_memory` 可切换旧方式进行消融。
2. 对“分类器结束但效果未完成”及持续无目标进展，中间层可请求 Agent 选择
   `continue` / `reapproach` / `stop`。恢复提示词在 Markdown，动作仍经控制租约。
   `continue` 保留记忆，`reapproach` 只做 IK 接近，不替 VLA 抓取或放置。
3. 为本机 Blackwell 增加可选单 patch 线性投影，替代极慢的 Conv3D。使用原权重，
   但 BF16 舍入不同，动作轨迹会改变。独立随机输入测量约 1.237 秒 → 0.000099 秒，
   最大绝对差 0.0078125；这只是该算子测量，不是端到端性能或 Agent 增益。
4. 光追保留，降噪关闭；读取同一 Color buffer 时使用 CUDA 接口。首帧 PNG 与 CPU
   读取完全相同，后续轨迹不同。不能据单次成功声称已根治 SAPIEN 驱动阻塞。

### 权重与贡献边界

使用已下载且 SHA256 验证通过的官方任务执行权重：
`workspace/mem0/models/executor/checkpoints/cover_blocks/final_step30000.pt`，约 15.3 GB。
SHA256：`b9e8fc2a8fecf3635519d12da12911c7193507b714fdd2c26bca14588d60786a`。
严格加载所有模型键。没有重新训练，也没有加载官方 Planner。

Agent 决定技能与位置绑定，IK 使用仿真位姿接近该目标，VLA 完成抓取、搬运、
释放与退让；环境负责物理验收。初次使用 IK 由实验模式固定，**不是 Agent
自主发现要使用 IK**。成功这一轮 `handoff_calls=0`，因此**尚未证明 Agent 恢复
机制提高成功率**。前三个覆盖目标各只有一个合法候选；揭盖位置由 Agent 根据
初始 RGB 选择。下一步研究贡献应通过冻结权重、渲染、记忆方式与预算的消融验证。

885 个 VLA 动作不含 IK 内部物理步，不能与历史全 VLA 的 1128 步直接比较总成本。
本轮还同时改变了记忆交接、计算与读取路径，不能把结果差异单独归因于 Agent。

## 对中间层最有价值的失败记录

普通渲染 IK 组的首个技能在 177 步后收到两次结束信号：

1. 后端报告 `execution=completed`，控制权正常交还。
2. 环境仍为 `covered:left=false`，Executive 判定 `effect=failure`。
3. Agent 随后请求索引 0 重试；此时一次尝试预算已耗尽，合法候选为空。
4. StructuredPlanner 拒绝该索引，未下发新的动作，整个任务没有被标记成功。

这验证了“执行器结束”和“目标实际完成”必须分开处理，以及合法候选校验确实
拦截了模型的不合规请求。**当前没有自动修正抓取的恢复策略**，也没有验证
一种新的、更优的交接方法；该记录可以作为后续研究交接条件与恢复规则的案例。

## 渲染兼容性与证据边界

smoke-03 的 `SIGUSR1` 堆栈停在：

```text
envs/camera/camera.py:336  camera.get_picture("Color")
envs/_base_task.py:461    get_obs
simulation/rmbench_worker.py  chunk
```

上游有 [Blackwell / SAPIEN 3.0.0b1 同类阻塞报告](https://github.com/RoboTwin-Platform/RoboTwin/issues/477)。
本机已确认阻塞位置，尚未确认底层驱动根因。关闭未使用相机没有彻底解决问题；
其首个技能的 95 个动作及 95 张头部图像与第一轮逐项完全一致。

普通渲染的配对测试完成了运行流程，没有再次发生上述阻塞，但两种模式都未
完成整任务。它改变了图像外观，不能替代官方光追条件下的评测。
一次种子不足以区分视觉分布、控制器交接和策略随机性的影响。

模型使用发布的任务专用 checkpoint 和归一化统计，SHA256 校验通过、参数严格
加载。兼容改动包括 SDPA、FP32 动作头输入显式转换和可配置渲染。
这不是 π0.5 base 的零样本评测。
