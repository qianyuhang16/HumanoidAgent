## 本次行为变化

### 模型实际收到图片

State、Execution、Verification 返回的本地图像由 Hook 收集，在下一次推理中以真实多模态字节发送。取消模型侧的 `get_resource` 动作；内部 Memory 资源读取接口仍供宿主、桌面和模型适配层使用，不能一起删除。

纯图片 State 返回值在模型侧只表示图片引用。图片标签只含 `ref`、相机名或描述，以及已提供的尺寸。例如：

```json
{"ref": "image_1", "camera": "agentview", "width": 512, "height": 512}
```

图片是独立附件，不是根据 JSON 描述生成的画面。默认保留最近两张，按附件顺序提供标签；稳定引用不随附件重排、淘汰或 Session 重载而重新绑定。后台未送给模型的帧不分配长期短引用。图片仍是历史快照，动作后是否需要新观测由 Planner 判断。

Execution 即使只返回图片，也必须保留动作参数、完成状态、call_id 和证据关联。不能将“纯图片 State 的显示精简”套到所有工具域。

### 模型上下文与审计记录分开

模型默认不接收 Session/Task UUID、运行计数、资源路径、TTL、部署配置和无意义的空字段。原始 journal 与 Session 仍保存审计、控制恢复所需信息。

工具结果在模型侧压平，保留实际业务输出、错误和验证结论。同一次结果不在上次结果和最近调用中重复。进度按调用合并；最近调用单独保留动作参数，避免 wait 或高频遥测挤掉决策依据。

不递归按字段名删除第三方业务 payload。平台自身决定有用的业务字段；核心不理解 RoboCasa 位姿、步号或任务谓词。

### 图片引用与 Skill

需要图片的 Tool 顶层字符串参数声明 `format: image-ref`。模型传 image_1，Runtime 在分发前解析为真实资源 ID。只有这些声明过的参数会被解析，其他业务参数保持原义。

同一短引用还可用于 ask_user.resource_ids、evidence_get.id、memory_write.source_ids、finish.evidence_ids；持久证据关系保存真实资源/记录 ID。引用在 Session 内有效，跨 Session 应通过原始证据重新加载图片。

Skill 完整 Markdown 继续用于平台装配及协议传输；`SkillStore.read()` 只提供正文分页和输入 Schema，offset/total_chars 均相对于正文。正文在加载时拆分一次，图片参数声明在工具注册时解析一次。

后续 Skill 只描述必要参数、用途、结果含义和失败处理，不让模型搬运内部状态，不为凑标题重复内容，不写固定任务工作流。约束见 Agent.md 和 skills/README.md。

### 连续对话与桌面

默认对话模式展示用户消息、Agent 提问和回复；调用详情模式展示参数、进度、结果、错误及资源。移除品牌 Logo 和冗余页脚描述。

waiting_user、paused、completed、failed 会话允许追加消息继续同一任务，保留历史和累计预算。运行中需先暂停 runner；取消、预算耗尽或停止未确认不能通过追加消息绕过。最新用户补充独立进入规划上下文。

`/api/sessions/{id}` 增加 conversation 和 conversation_has_more；history 支持 conversation=true。前端、接口和测试要一起合并。预览继续是只读视角，不能当成模型已看到的正式图片证据。

### RoboCasa 分支

新增 TabletopGrasp 本地场景和 PlaceVegetablesEvenly 双食材入锅 profile；前者定义场景与成功谓词，不包含解题动作序列。

capture_image 返回空业务 payload 与图片资源；相机、尺寸、场景和帧信息存在资源 metadata。模型只看到图片标签。localize_pixel 改为接收 image、row、column，平台自行找相机并检查图像归属、边界及过期状态。

observe 返回 robot_state 和 simulation_steps；成功动作只返回原语结果，进度只返回步号，Verification 返回进度、依据和独立结论。失败保留原始证据。

## 接口迁移对照

| 旧用法 | 当前用法 |
| --- | --- |
| 模型 get_resource 再读取图片 | 工具返回后自动附图，无额外模型动作 |
| context.data.session.goal | context.data.goal；Session 状态通过 Runtime 获取 |
| context.data.user_input.payload.answer | context.data.user_input.answer |
| last_result.result.payload | last_result.output，空业务输出可省略 |
| last_result.result.verification | last_result.verification |
| 模型 images 内含资源 UUID、URI、时间戳 | images 仅含标签；内部资源在 PlanningContext.image_resources |
| 复制 PlanningContext(data, schema) | 包装现有上下文时必须保留第三个 image_resources 参数 |
| read_skill 返回完整 YAML + 正文 | 返回正文分页和 input_schema；documents() 保留完整文档 |
| RoboCasa localize_pixel(camera, row, column, episode_id, simulation_steps) | localize_pixel(image, row, column) |
| 相机结果 resources.rgb 作为模型图片入口 | 图片附件及 image_1 等短引用 |

纯图片 State 的 last_result 可以是 `{"images": ["image_1"]}`，不能假定所有结果都有 status/output。Execution 和 Verification 保持各自的结果语义。截断结果仍保留证据分页入口。

本次未提供旧 image_reads 存档的通用迁移器。当前仍使用的会话没有该字段；需要读取更早版本存档的团队应先离线迁移，不能把旧资源 ID 冒充新帧。

## 高冲突文件与保留原则

| 路径 | 合并时保留的行为 |
| --- | --- |
| planning/context.py、base.py、model.py | 模型字段投影与内部图像字节引用分离，动作参数不被进度覆盖，Execution 事实不被图片精简删除 |
| planning/actions.py、prompts.py | 不恢复模型 get_resource；保留 image-ref、错误恢复和执行/任务成功的区分 |
| runtime/agent.py、session.py | 图片 Hook、稳定引用、用户补充、预算累积；暂停不等于动作停止 |
| skills/store.py、tools/registry/registry.py | 正文与部署信息分开，入口一次解析；合法 JSON Schema 不能使图片参数发现崩溃 |
| memory/store.py | 原始 journal 不被显示精简改变；进度合并只影响检索视图 |
| interfaces/service.py、interfaces/web/、desktop/ | 连续对话与调用详情共用真实会话；API 和前端字段同步 |
| workspace/robocasa/runtime/ 与 skills/state/ | localize_pixel 实现和 Skill Schema 必须成套更新，不恢复 episode_id 参数搬运 |
| .gitignore、README.md、configs/ | 保留当前目标分支边界，只追踪 example 配置，保留本机资产与密钥忽略规则 |

文件路径未写 src 前缀的核心模块均位于 src/primitive_vla/。不要对整个冲突批量使用 ours/theirs：接口、实现、测试和文档必须采用同一版本语义。
