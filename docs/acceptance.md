# 需求与验收映射

测试执行：`python -m unittest discover -s tests -t . -v`，使用标准库测试框架和离线替身。

| 验收重点 | 当前证据 |
| --- | --- |
| 新 Tool 不修改主循环 | 创建 Agent 后动态注册任意命名能力，再发现并调用 |
| Skill 可发现、按需读取 | 版本索引、Markdown 原文读取、分页接口，读取不会启动工具 |
| Rule 不固化为工作流 | 生产代码只有框架动作分发；工具顺序完全由注入 Planner 输出决定 |
| 接口失败后的纠正 | Planner 读取 Schema 错误后修正参数，同一 Session 继续 |
| 执行结束与效果分离 | Execution 完成后 Verification 返回失败，保留不同记录与调用关联 |
| 验证失败后的调整 | 测试决策器读取验证失败证据后主动选择新的 State 调用 |
| 控制互斥 | 并发争抢、别名重叠、同实例冲突拒绝、不同实例独立、State 仍可运行 |
| 停止确认 | 取消拒绝、确认超时、Provider 异常均保留资源；确认后释放 |
| 异步事件循环 | 等待期间不持续推理，完成事件唤醒，推理期间的事件不丢失 |
| Session 管理 | 暂停/恢复预算、用户输入、同步执行期间暂停、取消、时间和调用预算 |
| 重启恢复 | 未结束调用重新占用资源，Provider 不重放动作；Session 计数保留 |
| Memory 生命周期 | 长期记录重开可读、短期 TTL、错误/验证证据保留、来源不可覆盖 |
| VLM 边界 | 不同模型复用同一 ModelPlanner 与提示词；模型通信不依赖 Planning/Memory/机器人 |
| 工作记忆遗忘 | Markdown 正文直接读取；删除短期文档后不再进入上下文；原始事件与未结束调用仍可恢复 |
| 长期整理 | 周期触发、无变化不调用模型、上下文预算、来源版本、合并归档、并发修改使提案失效 |
| 桌面历史与记忆分离 | 时间线详情、复制和翻页读取 journal；Memory 浏览读取当前工作文档 |
| 多模态与上下文 | 原始数据独立存储、外部 URI 只登记、长记录分页、上下文长度上限 |
| Hook | 三域扩展、进度关联、前置拒绝、后置观察者错误不篡改执行事实 |
| 用户地图选点入口 | ask_user 携带地图资源；respond 将任意选点数据写入 Memory |

目前测试验证的是通用框架的行为与接口边界。测试中的决策器和 Provider 不是实际模型/机器人，
因此不能据此宣称 VLM 理解了 Skill、具有真机自主规划能力，或搬运任务已在真实环境验收。

真实本体的相机/感知/SLAM、建图、导航、VLA/IK、具体 Verification、地图展示与联调
仍需相应能力扩展。已有具体环境和模型接入的证据记录如下。

2026-11-12 VLM/Memory 重构：模型通信移至 `vlm/`，Planning 与定时整理复用生成接口。
运行存储改为 Markdown、文件索引和独立 JSON journal；按用户要求移除旧数据库迁移及兼容代码。
核心快照在不包含具体仿真 Provider 的独立目录中通过 **84 项 Python 测试和 10 项桌面测试**，
包括真实本机 Runtime 子进程的启动与退出；这些自动化检查没有运行模型 API 或仿真器。
真实 DeepSeek API 检查覆盖图像描述和结构化决策；同一个 VLM 实例还将两份长期笔记合并，
来源版本均可回读。以上模型检查没有执行机器人动作，也不代表任务成功率评测。
