# Skill Markdown 规范 v1

Skill 是 Planning 阅读的知识文档，不是可执行工作流。框架不会从 Markdown 解析动作序列，
不会把文中的相似度阈值、业务状态或准备条件转成通用 Runtime 检查。

每个能力包提供 `skills.json` 索引：

```json
[
  {
    "id": "organization.capability@1",
    "version": "1.0.0",
    "description": "能力简述，用于按需发现",
    "path": "capability.md"
  }
]
```

`ToolSpec.skill_ref` 使用索引 ID。需要同时维护不兼容版本时使用不同 ID；小版本可沿用 ID，
更新 `version`。读取结果始终带版本。路径必须在能力包目录内。本仓库的索引为空，不内置任何实际技能。

Markdown 建议包含以下章节。统一描述结构，不强制统一动作步骤：

```markdown
# 能力名称

## 能力描述
能完成什么，以及能力边界。

## 适用条件
适用环境、机器人状态、可观测要求；明确哪些条件由 Planning 判断。

## 所需输入
目标、用户信息、参考资源、坐标系和状态要求。

## 准备方法
缺少信息或条件时，可考虑哪些 State/Execution 能力。
描述选择依据，不假设每个任务都必须按同一顺序执行。

## 调用方法
引用实际注册的 Tool 名称、主要参数和资源格式。

## 完成验证
可调用的 Verification 能力、判断依据及不确定时如何补充证据。

## 失败处理
可能原因、补充观测、可选调整方式、重试边界以及何时向用户求助。
```

参考图像、地图等用资源引用或 Provider 可解析的 URI 表达，实际数据转换由适配代码完成。
机器人控制资源互斥和接口 Schema 属于代码契约，不依赖文档自律。
