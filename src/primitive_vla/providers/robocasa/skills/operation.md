# RoboCasa 操作与验证

## 能力与适用条件

在已经初始化的 PandaOmron 厨房仿真中获取观测、移动底盘和机械臂、控制夹爪并检查任务效果。
任务名称、目标语言和初始场景由宿主选定。先读取 `state.robocasa.observe` 的 `task_language`，
确认用户目标和环境任务一致；本 Skill 不规定解题顺序，也不提供整条专家轨迹。

## 所需输入与准备

状态观测提供世界坐标下的机器人位姿、仿真步号和时间。`capture_image` 提供 RGB 资源引用，
可以选择 agentview、agentview_right、wrist、navview，并按需保存米制深度。
需要物体世界坐标时，先在图像中选择目标表面像素，再调用 `state.robocasa.localize_pixel`，
传入相同相机、从图像左上角起算的 row/column，以及采集结果的 episode_id 和 simulation_steps。
该工具使用相机深度与标定进行几何回投，不负责目标识别、可达性或抓取点判断。
仿真推进后旧步号会被拒绝，应重新采集；不要把背景像素或投影坐标直接当成可执行抓取姿态。
没有可靠目标位置时先补充观测或请求帮助，不编造抓取坐标。
Planner 适配器需要实际加载图像资源，JSON 中出现资源 ID 不等于模型已经看见图像。

## 调用方法

按需发现并检查 `execution.robocasa.*` 的 Schema 与描述。`move_to` / `move_delta` 用于末端位移，
`set_gripper` / `release` 控制夹爪，`scripted_grasp` 是局部抓取控制原语，不保证抓住物体。
`move_base` 与 `navigate_to` 用于底盘调整；后者直接向坐标运动，没有全局避障与路径规划能力。
先从图像判断通路，必要时分段调整。保持合理的动作步数与小幅位移，依据新观测继续决策。

所有动作都会推进同一个仿真，因此共用 `simulation` 控制资源。异步调用返回 call_id 后，
通过状态查询或事件等待终态；冲突时应等待或请求取消，不重复提交动作。
执行中的 `observe` 读取最近完成步的缓存；相机采集在原生线程上排队，不保证立即返回。

## 完成验证

动作完成不代表任务完成。调用 `verification.robocasa.task` 读取当前 episode 的原生成功谓词。
可传入本任务中已经结束的动作 call_id 关联证据。该验证属于仿真真值反馈，不是视觉模型判断。
工具异常意味着验证未完成，不能当作成功或把缺失结果猜成失败。

## 失败与恢复

根据失败证据决定重新观测、调整目标/姿态、改用其他原语、请求帮助或结束任务。
在当前状态继续，不通过 reset 重做 episode。本集成不暴露 reset、专家任务脚本或 VLA 工具。
暂停 Planning 不会暂停在执行的动作；要停止动作必须请求取消并等待确认。
同一进程内可以暂停/恢复任务；进程重启不保留仿真物理状态，不能把重建环境当作恢复旧任务。
