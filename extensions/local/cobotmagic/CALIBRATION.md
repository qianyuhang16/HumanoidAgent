# COBOT MAGIC 双臂标定操作手册

启动一个网页，完成 **相机内参、左臂外参、右臂外参、左右臂 TCP**。TCP 使用独立的固定点流程，见 [TCP 操作手册](TCP_CALIBRATION.md)，无需重做相机标定。左右臂顺序可以交换。程序只读取 ROS 图像和关节反馈，不发送移动、使能、夹爪指令；机械臂由你通过已有示教器操作。

## 1. 到底需要标定什么

| 项目 | 用途 | 次数 | 本程序支持 |
|---|---|---|---|
| 前置 RGB 相机内参 K、D | 描述投影和镜头畸变 | 同一相机、分辨率、镜头设置共用一份 | 是 |
| 前置相机 → 左臂基座外参 | 把相机中的三维点变到左臂坐标系 | 左臂一份 | 是 |
| 前置相机 → 右臂基座外参 | 把相机中的三维点变到右臂坐标系 | 右臂一份 | 是 |
| 左右夹爪 TCP | 确定真实抓取点相对机械臂末端的位置/朝向 | 每个工具分别测定；换工具需更新 | 是，固定点法自动求位置；坐标轴沿用末端约定 |
| 目标的深度或工作平面 | 从像素获得物体三维位置 | 接入深度并核对配准/尺度，或标定桌面平面并结合目标高度 | 否 |
| 实物定位误差 | 确认整条链在真实工作区准确 | 使用独立测量点验证 | 否，不自动运动 |

**相机内参通过不代表任何一条机械臂外参通过。** 旧 `intrinsics/result.json` 中的 `arm: right` 只是采集关节来源，不能解释为“右臂标定完成”。网页内参步骤明确标记为双臂共用。

这里只支持固定前置相机的 eye-to-hand。`arm: left` 表示读取左臂关节，**不是使用左腕相机**。腕部相机需要不同的标定流程。

## 2. 启动统一网页

先在旧采集终端按 **Ctrl+C**。从项目根目录运行：

```bash
.venv/bin/python -m primitive_vla_cobotmagic.calibration web
```

打开 **http://127.0.0.1:18084**；远程 IDE 转发 18084 端口。端口占用时可添加 `--port 18085`。退出服务仍用 Ctrl+C。

双臂只使用一份 `extensions/local/cobotmagic/configs/calibration.yaml`：相机、标定板、URDF 和误差阈值共用。网页选择左/右臂步骤时自动确定关节来源，不用复制 YAML 或手动改 `arm`。桥地址默认 `10.192.73.147:48055`。自定义配置用 `web --config /path/to/calibration.yaml`；低层单臂采集命令 `capture` 必须显式指定 `--arm left` 或 `--arm right`。已有左右臂标定结果仍分别保存并自动复用，不需要重新标定。

网页上方选择步骤，下方选择历史批次并点“继续所选批次”，或点“新建批次”。**上方选择只是在查看步骤，点击继续/新建才切换采集。** 当前采集对象和完整保存目录会持续显示。

- 空格：保存训练样本；V：保存独立验证样本。先点击网页空白处，让网页获得键盘焦点。也可以点按钮。
- 建议每步 20–30 组训练 + 4–6 组验证，程序最低要求 12 + 4。
- “求解并验证当前批次”在网页完成离线计算，显示是否通过及具体误差。
- 已求解后再采样，旧结果会显示“需重新求解”。
- 重新夹持板、改变板安装方式时，新建外参批次。新批次不覆盖旧批次。
- 切换步骤会清空当前帧和停稳历史，防止把上一条臂的样本记到另一条臂。
- 多个浏览器共用同一当前采集对象；旧页面发出的过期操作会被拒绝。建议一个操作者使用一个窗口。
- ROS 离线时可以浏览已有结果，选择批次后程序重试只读连接；无有效数据不能保存。

## 3. 准备标定板与相机

已有打印文件：`workspace/cobotmagic-calibration/board/board-a4.svg`。以后确需生成另一张板时可运行（会覆盖输出板图；本次无需运行）：

```bash
.venv/bin/python -m primitive_vla_cobotmagic.calibration board
```

当前这张实物板的格长已测为 **27.2 mm**，共享配置已采用 `square_m: 0.0272`。按原图案等比例缩放，标记边长设为 **16.32 mm**（`marker_m: 0.01632`，5×7 格）。**现有板无需重新打印。** 原 SVG 标称 30 mm，实际标定以实测尺寸为准。请横向和纵向各跨几个格测量后取平均，确认两方向都接近 27.2 mm；若不一致，不能按等比例缩放处理。纸贴在平整硬板上，避免弯曲、反光、纸张相对背板滑动；夹爪不要遮住主要图案。

固定前置相机支架和机器人基座。标定时保持镜头、分辨率、裁剪及校正方式一致。采集手眼外参前核对 URDF 与实际机械臂，否则再多图片也不能弥补错误运动学。

### 板应该夹在哪里

板不必夹在中心，也不必与夹爪轴对齐；板相对末端的固定安装变换会同时求解，不需要你手量安装偏移。夹在边缘本身不是标定错误。需要满足的是“刚性固定、板面平整、图案可见”：

- 夹住硬质底板或牢固连接到底板的夹持柄，不能只夹纸张、弹簧夹的活动部分或会转动的薄边。
- 尽量有足够的接触面积和夹持深度，避免整块板仅靠一个小接触点悬着；短而刚的连接通常更容易保持稳定。不要为了夹紧把板夹弯。
- 纸张贴牢，不能相对底板滑动或鼓起；亮面保护层应避免反光遮住角点。
- 夹爪尽量位于图案之外，给棋盘格和标记留出视野。测试不同姿态时观察底板是否下垂、转动，固定相机是否被碰到。
- 每次改变夹持位置/方式都开新批次；一批内不能重新夹持。不要在运动中用手扶板。

只要板相对末端固定，换一个夹持位置重新采完整一组，理论上仍应得到同一相机到基座变换；板的安装变换会不同。若夹持关系在一组中变化，则不存在一份固定安装变换能解释全部样本，会导致残差变大。

### 为什么实机能到达，URDF 却提示超范围

URDF 的关节限位是模型文件里的参考数值，不是本程序从控制器读取的实机当前限位。模型版本、零位约定、关节顺序、弧度/角度单位或边界精度不一致，都可能使反馈落在模型范围之外；不能仅凭这一提示判断实机碰到限位。

只读标定现在按**原始反馈角度**计算 FK，不再复用运动指令的限位拒绝逻辑，不截断角度、不自动换算或绕回角度。超范围时网页显示关节名、实测角度、参考上下限和超出量，样本及求解结果保存 `urdf_limit_exceedances`；离线求解同样保留这些诊断。NaN、无效长度、过期数据、未停稳等仍拒绝。

这仅取消了只读测量的错误拦截。URDF 的连杆几何、关节轴和零位仍必须正确；内部残差通过也不能证明这些约定与实机完全一致。运动脚本/IK 的限位检查仍保持严格，未改动实机控制器或模型限位。

## 4. 相机内参：只做一份

1. 选“前置相机内参（双臂共用）”。已有通过结果且相机成像设置没有变化，可以直接复用。
2. 若重做，点击“新建批次”，手持标定板，覆盖画面中心、四角，以及不同距离和倾角。
3. 每次停稳再记录；训练和验证都要覆盖多个位置，验证图像不能只是刚才训练图像的重复。
4. 点“求解并验证”。默认训练 RMS 和验证图像重投影误差都需不超过 1 px。

此步不要求板固定到机械臂，也不要求机械臂停稳；当前桥仍需原有图像/关节流就绪。结果包含 `K`、`D`、图像尺寸。新建左右臂外参批次前，当前选用的内参批次必须通过且没有待重新求解的新增样本。

## 5. 左臂、右臂外参：分别做

以左臂为例：

1. 板刚性固定到**左臂末端**，检查夹持处和背板不会相对末端旋转或滑动。前置相机不动。
2. 选“前置相机 → 左臂基座”，点“新建批次”。确认右侧“当前采集”为左臂。
3. 用已有示教器改变左臂位置和朝向。每次运动后停约 **2 秒**，页面提示“可以记录”再按键。
4. 让板在工作区内具有不同位置，并绕不同方向倾斜。不要只平移、只绕一个轴转，也不必追求极限姿态。
5. 采训练 20–30 组，再采独立验证 4–6 组，点击“求解并验证”。
6. 看误差：默认训练、验证最大位置差都需 ≤20 mm，角度差 ≤5°。未通过应检查原因或新建批次重采，不要只放宽阈值。

右臂同样操作：将板固定在右臂末端，选择右臂步骤，**新建右臂批次**。两臂之间可重新夹板，但每一批采集中必须保持安装不变。左右臂距离约 60 cm 不能替代这两份外参。

程序用反馈关节角和 URDF 算 `base_link → link6`；联合图像板位姿求解：

```text
T_base_from_tip(i) @ T_tip_from_board
    = T_base_from_camera @ T_camera_from_board(i)
```

`T_base_from_camera` 是相机光学坐标到所选臂基座坐标的变换（米）；两份 URDF 都叫 `base_link`，所以还必须看结果的 `arm`。`T_tip_from_board` 是末端到板的安装变换，**不是夹爪 TCP**。

最大图像/关节时间差默认 **400 ms**，数据年龄上限 0.5 秒（含请求耗时），最近 0.8 秒关节变化需 ≤0.008 rad。它是停稳采样检查，不是硬件同步；400 ms 不代表可以运动中采样。修改配置要重启服务。

每个外参批次保存创建时使用的内参副本。后来重做内参不会暗中替换旧外参批次的输入；若成像设置或相机安装关系改变，需要新建对应外参批次。

## 6. 工作区目录与旧数据

```text
workspace/cobotmagic-calibration/
  README.md                             # 工作区说明
  workspace.json                        # 每一步选用的批次、旧数据导入来源
  board/                                # 打印用板图
  camera-intrinsics/front/runs/<批次>/   # 双臂共用内参
  handeye/front-to-left-base/runs/<批次>/ # 左臂外参
  handeye/front-to-right-base/runs/<批次>/# 右臂外参
  tcp/left-tool/runs/<批次>/              # 左臂 TCP
  tcp/right-tool/runs/<批次>/             # 右臂 TCP
```

批次包含 `manifest.json`、`samples/<ID>/image.jpg`、`sample.json`、`result.json`；外参还有 `robot.urdf` 快照。首次启动会把旧 `intrinsics/`、`handeye-left/`、`handeye/` **复制**到对应步骤的 `imported-*` 批次，保留原目录；只导入一次。旧服务未停止时拒绝复制，避免复制到正在写入的数据。

旧的成功内参会显示为“内参通过”，失败的左臂记录保留为“未通过”，缺失的右臂外参显示“未开始”。新采样批次名带 UTC 时间和随机后缀。`measured-27p2mm-*` 是按此次实测尺寸在原数据副本上重新求解的批次，`board-remeasurement.json` 保存来源和缩放假设；原批次保留。别在旧目录继续采样后期待它自动同步到新工作区。

修改 `capture` 阈值可以续采原批次，新样本会保存当时的 `capture_policy`。修改板、机械臂、模型、内参等会要求新批次。JPEG 和 URDF 有校验值。内部检查通过时仍标记 `physical_accuracy_verified: false`。

旧的 `capture --phase ... --session ...` 和 `solve --session ...` 命令继续可用，但日常操作建议统一用网页。若想离线重新求解某一批次，停止采集后对网页显示的批次目录执行 `solve --session <目录>`。

## 7. 标定通过之后还缺什么

- **夹爪 TCP**：测定夹爪实际抓取中心相对 `link6` 的位置和朝向，左右臂分别处理。现在可以用网页中的左右臂 TCP 入口完成固定点标定；操作见 [TCP 操作手册](TCP_CALIBRATION.md)。该流程不从板的安装偏移猜测 TCP。
- **像素到三维**：当前桥只给 RGB，没有深度或 CameraInfo。单个普通物体的像素位置不能直接给出任意三维坐标；需要接入可靠深度并验证与 RGB 对齐，或测量桌面平面、结合物体高度做几何定位。
- **真实误差验证**：用不参与拟合的已知位置/独立测量点，在实际工作范围比较估计位置和实测位置。网页的留出验证只能检查内部一致性，不是实物精度保证。
- 路径可达性、障碍物、运动范围和控制接口仍由后续运动流程检查。标定网页不直接接入移动按钮。
