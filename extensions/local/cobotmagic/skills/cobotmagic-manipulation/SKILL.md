---
name: cobotmagic-manipulation
description: 使用 Cobot Magic 的 IK、VLA 和单臂复位工具完成真实操作。适用于机器人操作任务；普通问答无需执行运动。
---

用户请求真实操作时，自行选择适合的可用工具和模型。以下是本机 VLA 的调用前提，不是所有问题的固定流程。

- **接近物体优先同侧、就近用臂。** 结合当前图像和 `perception.segment` 返回的 `arm_context`：比较两臂标定坐标下的距离，优先 `preferred_arm`；左侧附近的物体通常先用左臂，右侧附近通常先用右臂。不能只按像素中线硬分左右，也不能将“某臂 IK 成功”等同于“最适合用这条臂”。用户明确指定、遮挡、持物状态或任务协作需要可以改变选择，但应说明具体依据。
- **一次局部 IK 失败不代表该臂不可达，更不是让另一条臂跨过来接触物体的充分理由。** 检查失败原因和当前起点，结合重新观察或已有规划能力处理；工具仍无法为同侧臂给出路径时，报告具体受阻原因。只有场景/任务证据支持另一臂接近时才换臂，不以“另一臂算成功了”作为唯一依据。
- **每次调用 VLA 前，必须先用 IK 将机械臂移动到目标物体上方。** 使用 camera.observe、perception.segment、robot.plan_hover 定位并规划，再调用 robot.execute；只有返回 arrival_verified=true 才算完成准备，solved=true 或生成计划不算。计划和执行使用目标对象对应的 detection_id。工具返回 preparation_id，交给 vla.run；一次调用消耗一次准备，不凭聊天记忆声称已准备好。
- VLA 自己决定实际使用哪条臂。保留它完整的双臂和夹爪输出，不把 IK 准备臂当成 VLA 固定选臂，也不自行裁剪模型动作。若用户目标、物体布局或初始姿态不符合模型说明，应先处理或报告缺失条件。
- **从左臂操作切换到右臂前，必须先调用 robot.reset_arm(arm="left")，并确认 arrival_verified=true，然后再准备右臂；反向同理。** 根据 robot.arm_state 返回的 needs_reset 和 VLA 实际 used_arms 判断，不只依据原先选择的 IK 臂。若两臂都动过，应处理下一步不使用的那条臂；反馈不确定时不得声称已复位。
- 继续使用同一条臂时，`needs_reset` 不是要求立刻复位；它记录换臂前的交接需求。模型加载失败且未发动作时，不为“清空标记”重复复位，基于新反馈完成本轮必要准备即可。
- reset_arm 使选定臂六个关节回配置的 home，并使该臂夹爪回配置开度（默认 0 m、闭合；具体值见工具说明），另一臂沿用当前状态保持。复位会改变夹爪开合，不是放置物体的替代动作：若上一任务尚持物或位于不适合直接复位的位置，先完成放置/退出，再复位。到位结果同时核对关节与夹爪反馈。
- IK 和复位默认三秒轨迹；VLA 使用模型配置的频率和独立时长。到时、停止输出、task_success=null 都不表示语义任务完成。读取执行末帧或重新 camera.observe，验证用户目标，再决定后续工具调用。不要盲目重复倾倒等物理动作。
- VLA 执行后，结合执行前后图片判断用户要求的最终状态。默认由你在正常下一轮回复的 `assessments` 中记录判断，并同时选择下一工具或回复用户；无需另调验证工具。`outcomes` 是带来源与证据的可修订记录，文字 memory 也是可能出错的摘要。已经完成的子任务应推进；`unknown` 表示尚不确定，不等于失败。重试前说明实际证据，不能仅因夹爪松开或运行结束就认定抓放失败、增加时长重跑。配置 independent 时可参考独立验证结论，也可按需调用 `session.assess`；后续如何行动仍由你判断。
- robot.arm_state 跨聊天轮次保留复位需求；VLA preparation_id 只在当前轮有效。取消后核对返回状态，不能把取消按钮当作机器人急停确认。
